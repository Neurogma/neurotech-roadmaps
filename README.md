# neurotech-roadmaps

A small, curated learning system for navigating neurotechnology by **capability** rather than by collecting links. A node tells you what to learn and what it depends on; a roadmap connects those capabilities to a goal; a project gives you evidence that you can use them.

## Neurotech Atlas

The repository now includes **Neurotech Atlas**, a dependency-free interactive UI for navigating the knowledge base as a product: roadmap discovery, capability-family graph, evidence projects, paper guides and the underlying source library.

Open `app/index.html` locally, or read the [app documentation](app/README.md).

## How to use it

1. Pick a goal and read its roadmap.
2. Start at the first capability you do not already have. Prerequisites are stored in the node itself.
3. Work the exercise or project and keep the resulting notebook, analysis, code review or written explanation as evidence.
4. Branch only when the base path is stable enough to support the next method.

### Depth

- **Explorer:** field vocabulary, conceptual map, small commitment.
- **Builder:** implementation, public data, reproducibility and projects.
- **Researcher:** mathematical/methodological depth, primary literature, critical evaluation and open questions.

Depth labels describe the knowledge required, not a learner's status. Completing a roadmap is not a credential.

## Repository structure

```text
app/            Neurotech Atlas presentation layer
roadmaps/       goal-driven paths; YAML is canonical, Markdown is generated
nodes/          one YAML file per reusable capability
projects/       evidence-producing project specifications
resources/      one curated resource catalog
papers/         structured paper-reading guides
docs/           methodology, maintenance, reproducibility and safety
schemas/        machine-readable validation schemas
scripts/        validator + roadmap renderer
tests/          repository-level validation tests
```

There is deliberately no manually maintained graph store. Prerequisite edges come only from `nodes/**/*.yml`; any derived graph should be generated by tooling when needed.

## Where the first work usually happens

**Python + little neuroscience** → `neuroscience-basics` → `physiology-neural`.

**Neuroscience + little signal processing** → `signal-processing` → `eeg-fundamentals`.

**EEG + weak statistics** → `probability` → `statistics-inference`.

**Engineering + little physiology** → `neuroscience-basics` → `biological-signals`.

## Validate locally

```bash
python -m pip install -r requirements-dev.txt
python scripts/generate_roadmaps.py
python scripts/validate.py
python scripts/validate.py --strict-provenance
python -m unittest discover -s tests -v
```

Use `python scripts/validate.py --urls` for a best-effort external URL check. Strict provenance validation is designed to make resource maintenance explicit instead of silently allowing stale material to remain marked `active`.

## Evidence, provenance and maintenance

Every resource marked `active` carries machine-readable provenance: the authority/source class, the date it was last reviewed and the intended review interval. The date means that the catalog entry and its linked source were reviewed; it is not a publication date and does not guarantee that the source itself is immutable.

The validator treats non-`active` resources as unavailable to current roadmaps and prevents silently depending on `needs-review`, `deprecated` or broken resources. Scheduled CI runs strict provenance checks and external-link checks so maintenance becomes a recurring quality gate rather than an occasional cleanup.

See [`docs/methodology.md`](docs/methodology.md) for the data model and [`docs/maintenance.md`](docs/maintenance.md) for the review process.

## Scientific and safety boundaries

The repository favors public datasets, simulation and software work. It does not provide clinical training, invasive procedures or electrical-stimulation protocols. Human-subject work, clinical claims, invasive systems and stimulation require appropriate professional, ethical and regulatory pathways. See [`docs/safety.md`](docs/safety.md).

Important claims should be tied to primary literature, standards, official documentation or reputable institutional sources. See [`docs/methodology.md`](docs/methodology.md).

## Contributing

Add a node when it represents a reusable capability. Add a resource when you can explain why it is worth the learner's time and record its provenance. Add a project only when the output can demonstrate competence. Roadmap Markdown is generated; edit the YAML instead. Read [`CONTRIBUTING.md`](CONTRIBUTING.md) before submitting a change.

## Limits

This is a curated learning system, not a complete map of neurotechnology and not a substitute for a university program, supervised laboratory training, clinical education or regulatory advice.
